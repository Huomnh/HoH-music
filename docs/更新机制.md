# 自动更新机制

## 当前实现

版本说明页和 Windows 应用启动流程共用 `lib/core/update/update_service.dart`：

1. 请求 `https://api.github.com/repos/Huomnh/HoH-music/releases`。
2. 忽略 Draft 和 Pre-release，只考虑正式发布的 Release。
3. 读取 `tag_name`，兼容 `v0.1.1`、`0.1.1` 和 `0.1.1-beta.2`。
4. Windows x64 只选择文件名同时包含 `Windows`/`Win`、`x64`/`amd64` 且扩展名为 `.exe` 的资产；如果有 `Setup` 安装包，优先选择它。
5. 与 `AppConstants.version` 比较，只有检测到更高版本并且存在匹配安装包时才判定为可更新。
6. 版本说明页可点击仓库链接和安装包链接，统一通过 `url_launcher` 交给系统默认浏览器打开。

启动时的 `OptionalUpdatePrompt` 是非强制更新提示：明确发现新版本时在右上角展示可关闭的提示卡，不遮罩、不阻断播放和页面交互。用户可以点击“稍后”继续使用，也可以在版本说明页重新检查；网络失败、API 限流、Release 缺少匹配安装包时不显示提示。

Debug 构建默认不在启动时访问 GitHub，避免测试和热重载产生大量网络请求；版本说明页的“重新检查”仍可以在 Debug 中手动验证。Release 构建启动检查默认启用。

## 发布约定

每次发布新版本时：

1. 修改 `pubspec.yaml` 和 `lib/shared/constants.dart` 的版本号，并同步变更文档。
2. 使用 `v<版本号>` 创建 GitHub Release，例如 `v0.1.1`。
3. 上传 Windows x64 安装器，推荐命名为 `HoH-music-Setup-<版本号>-Windows-x64.exe`。
4. Release 必须是 Published 状态；Draft 和 Pre-release 不会触发正式用户更新。
5. 在 Release body 写入简短更新说明；应用会去掉 Markdown 标记后展示。

当前实现是“打开浏览器下载 + 用户运行安装器”的更新流程，不会在程序内静默替换正在运行的 exe。这样可以继续使用现有 Inno Setup 安装器、桌面快捷方式和安装位置选择逻辑。

## 后续增强

- 为 Release API 增加固定代理或镜像配置，改善受限网络环境下的可达性。
- 发布带 SHA-256 的校验文件，在下载后增加完整性校验。
- 如果未来需要真正的一键安装，可增加独立 updater 进程：主程序退出后由 updater 替换文件，再重启主程序。该功能需要额外的 Windows 进程生命周期测试。
- Android、iOS、macOS、Linux 需要各自发布格式和平台资产筛选规则，不能直接复用 Windows `.exe` 规则。
