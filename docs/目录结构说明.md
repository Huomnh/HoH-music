# 当前目录结构

本文仅列出仓库里实际存在并参与当前应用的目录。未来平台或尚未实现的功能写在路线图中，不保留仅含空类的目录占位。

```text
lib/
├── app.dart, main.dart                 # Flutter 启动与应用根
├── core/
│   ├── audio/                          # MediaKit Player、播放状态与偏好
│   ├── database/                       # Drift schema、迁移与本地索引
│   ├── metadata/                       # 标签、封面与文本匹配
│   ├── remote/                         # WebDAV 客户端、连接设置
│   └── source/                         # LX JS 沙箱、音源管理、搜索/解析
├── features/
│   ├── library/                        # 本地曲库、列表、扫描、队列接入
│   ├── player/                         # 播放页、外观/播放/紧凑播放器设置、歌词
│   ├── remote/                         # WebDAV 用户界面
│   └── source/                         # 在线搜索、播放、下载及下载管理
├── platforms/windows/                  # 桌面窗口和 Windows 系统集成
└── shared/
    ├── theme/                          # 色彩、背景、字体、性能和主题包
    └── widgets/widget_kit/             # 玻璃材质、面板、描边与背景绘制

windows/                                # Flutter Windows runner 与构建配置
assets/                                 # 主题、图标和背景资源；audio/sources 不作为 Flutter 安装资源
music音源/                              # 安装器附带的独立 JS 脚本文件，供用户手动导入
docs/                                   # 交接、架构专题、协议与维护规范
scripts/                                # 本地构建辅助脚本
test/                                   # parser、WebDAV、来源、曲库和 widget 测试
```

## 代码依赖约定

1. 页面和 feature 可调用 `core` 与 `shared`；`core` 不依赖页面层。
2. Windows API/插件只从 `platforms/windows` 调用；跨平台新能力应定义最小接口，再由各平台实现。
3. 播放状态由 `core/audio/player_engine.dart` 与 `player_providers.dart` 提供；页面不创建第二个播放器。
4. 歌词解析、时间轴和 renderer 位于 `features/player/lyrics/`，共享同一播放时钟。
5. 生成文件（如 Drift 的 `*.g.dart`）由源 schema 生成，不手工改写。

Windows 安装包不包含用户音乐库或歌曲文件。脚本不作为 Flutter 内置资源加载/自动注册，而是放在安装目录的独立 `music音源/` 文件夹中，供用户从音源管理页面手动导入。`assets/audio/` 与 `assets/sources/` 不进入 Flutter bundle。

## 暂不保留空壳

自动歌单、跨端同步、Home Assistant、Android/iOS/TV 适配目前没有实现，因此不在 `lib/` 中放空类冒充模块。开始这些工作时再按本文件的依赖约定创建真实实现；当前产品状态与远期计划分别见 [架构说明](../音乐播放器架构文档.md) 和 [多平台构建评估](多平台构建可行性.md)。
