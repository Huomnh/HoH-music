# 跨平台互通实施方案

## 原则

Flutter/Dart 是共享 UI 与业务逻辑的主框架。歌词解析、播放模型、曲目/音质数据和主题定义尽量共用；系统媒体会话、后台音频、文件权限、窗口和遥控器输入按平台适配。共享代码不等于平台能力自动存在，任何平台只有完成工程、插件核验和设备验收后才能列为支持。

1. 单一曲目/播放队列/歌词时间轴/下载任务/主题数据模型。
2. 平台能力通过窄接口注入，未支持能力需显式 fallback 或隐藏，不能静默假成功。
3. 离开页面不应结束音频或下载生命周期。
4. 平台特有 UI 作为展示适配，不复制领域状态机。

## 当前已实现结构

```text
Flutter pages and widgets
          ↓
Riverpod state + shared models
          ↓
core services (PlayerEngine / SourceHost / Drift / WebDAV)
          ↓
Flutter plugins + current Windows adapters
```

当前播放状态由 `PlayerEngine` 及 providers 提供；歌词显示从统一 timeline/frame 读取；下载服务独立于搜索页组件。Windows 托盘、SMTC、窗口和桌面歌词位于 `lib/platforms/windows/`。部分 UI 组装仍有直接 Windows 依赖，尚未完成完整 PlatformServices 抽象。

## 可复用功能与待适配能力

| 能力 | 共享部分 | 新平台仍需实现/验收 |
|---|---|---|
| 播放与队列 | 曲目模型、控制状态、播放策略 | MediaKit 插件支持、焦点、后台播放、系统媒体会话 |
| 曲库 | 标签/曲目模型、扫描索引逻辑 | 文件选择、权限、SAF/Files API 等目录访问 |
| 在线来源 | LX 脚本契约、解析模型、UI 业务 | JS runtime/网络权限/后台生命周期和插件兼容 |
| 下载 | 任务状态、进度/暂停/恢复业务 | 后台执行、持久化路径与 OS 下载限制 |
| 歌词 | parser、timeline、renderer 输入、Flutter 页面 | 字体覆盖、性能档位、移动/TV 布局验收 |
| 主题 | theme bundle、动态背景定义、Flutter 绘制 | 文件导入导出入口、GPU/动画性能验收 |
| 桌面能力 | 不共享原生实现 | 桌面窗口、置顶、托盘、热键、歌词浮层各端重做 |
| TV | 播放与歌词领域状态 | 焦点/遥控器导航、10-foot 布局和安全区域 |

## 新平台实施顺序

1. 创建平台 runner 与构建流水线，确认每个直接/间接插件均支持目标平台。
2. 提取窗口、文件、媒体会话、后台音频/下载等 capability interfaces，保留 Windows 实现。
3. 以 Android 为首个移动端验证平台，随后 macOS/Linux，再评估 iOS 和 TV；顺序不代表现阶段已承诺日期。
4. 对同一套领域测试补平台 adapter tests 和真实设备验收。
5. 每次新增平台均更新本方案、README、许可清单和交接文档。

跨设备数据同步目前不在实现范围；协议选型待确认，见 [跨端同步技术方案](跨端同步技术方案.md)。
