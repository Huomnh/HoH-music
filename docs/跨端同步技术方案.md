# HoH music 跨端同步技术方案（待确认）

本文只做架构设计，当前不实现跨端同步。移动端、TV 和 Home Assistant 继续列为远期内容。

## 推荐方案：WebDAV 文件后端 + 本地操作日志

### 数据分层

1. 本地 SQLite/Drift 保存歌曲、歌单、收藏、播放进度和同步游标。
2. WebDAV 只保存版本化同步包，例如 `hoh-sync/state.json` 和按日期分片的操作日志。
3. 音频文件、封面和歌词不默认同步；本地/网盘曲目通过稳定标识引用，避免重复上传大文件。

### 稳定标识

- 本地歌曲：`local:<contentHash>:<normalizedTitle>:<normalizedArtist>`。
- WebDAV 歌曲：`dav:<sourceId>:<remotePath>`。
- 在线曲目：`online:<platform>:<songId>`。
- 歌单和设备使用 UUID，不使用机器路径作为实体 ID。

### 同步流程

```text
本地操作 → operation_log → 手动点击同步
                         ↓
              拉取远端 manifest / log
                         ↓
       按 cursor 增量合并 → 冲突解决 → 上传新日志
                         ↓
                 更新本地 cursor
```

### 冲突规则

- 收藏、歌单添加/移除使用带时间戳的集合操作，重复操作幂等。
- 歌单名称、排序、播放进度采用 `updatedAt + deviceId` 的确定性最后写入优先。
- 删除使用 tombstone，保留至少 30 天，避免离线设备重新上传已删除内容。
- 同步失败不影响播放；下次同步从上次成功 cursor 继续。

### 安全与可移植性

- WebDAV 凭据只进系统安全存储或本地加密存储，不写入同步包。
- 同步包 JSON 使用版本号和 schema migration，便于 Android/iOS/Windows 共用。
- WebDAV 客户端只负责传输，未来可替换为自建 HTTPS API，业务层不变。

## 方案对比

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| WebDAV + 操作日志 | 复用现有代码，NAS/网盘兼容，成本低 | 无实时推送，需要手动同步 | **首选** |
| 自建 REST 服务 | 实时同步、权限和查询更完整 | 需要部署服务端和账号体系 | 后续升级 |
| 云厂商数据库 | 多端实时能力强 | 绑定供应商，隐私和费用更高 | 不作为首版 |

## 暂不决定的事项

- 是否自动同步还是仅手动同步。
- 是否同步播放进度和歌词缓存。
- 是否允许同步用户自定义主题包。
- 是否需要端到端加密（如果同步包包含隐私数据，建议开启）。
